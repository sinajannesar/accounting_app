# نرم‌افزار حسابداری آفلاین

یک برنامه حسابداری ساده، آفلاین و فارسی برای ویندوز با Python و PyQt5. نسخه وب فروشگاه از React، TypeScript، Tailwind CSS و Flask API استفاده می‌کند.

## ویژگی‌ها

- **کاملاً آفلاین** — بدون نیاز به اینترنت یا سرور
- **رابط فارسی RTL** — مناسب کاربران فارسی‌زبان
- **پایگاه داده SQLite** — ذخیره محلی روی سیستم
- **تقویم شمسی (جلالی)** — برای تمام تاریخ‌ها
- **ماژول‌های اصلی:**
  - مدیریت سرفصل حساب‌ها (کدینگ ۵ سطحی)
  - ثبت اسناد حسابداری با پیگیری سررسید
  - صندوق (ورود/خروج وجه نقد)
  - دفتر معین، دفتر کل، تراز آزمایشی، صورت سود و زیان
- **خروجی Excel و PDF** از گزارش‌ها
- **پشتیبان‌گیری و بازیابی** دیتابیس
- **نمایش مبلغ به حروف** — زیر هر فیلد مبلغ (بدهکار، بستانکار، صندوق)، معادل ریالی مبلغ به‌صورت زنده به حروف فارسی نوشته می‌شود
- **هشدار سررسید** — هنگام باز شدن برنامه، اسناد سررسیدگذشته و نزدیک‌به‌سررسید (تا ۷ روز آینده) نمایش داده می‌شوند
- **چاپ رسید تک‌سندی** — از تب «اسناد حسابداری» یا «صندوق»، برای هر سند/تراکنش می‌توان یک فیش PDF (شماره، تاریخ، شرح، مبلغ به عدد و حروف، جای امضا) ساخت
- **داشبورد** — تب اول برنامه؛ خلاصه درآمد، هزینه، سود/زیان ماه جاری، موجودی صندوق، و نمودار میله‌ای روند ۶ ماه اخیر

## معماری دیتابیس

| ستون | نوع | توضیح |
|------|-----|-------|
| id | INTEGER | شناسه |
| code | TEXT | کد حساب |
| name | TEXT | نام حساب |

| level | INTEGER | سطح (۱=گروه، ۲=کل، ۳=معین، ۴=تفصیلی، ۵=تفصیلی شناور) |

| ستون | نوع | توضیح |
|------|-----|-------|
| id | INTEGER | شناسه |
| entry_number | INTEGER | شماره سند |
| entry_date | TEXT | تاریخ (شمسی) |
| due_date | TEXT | سررسید |
| description | TEXT | شرح |

### جدول `journal_lines` (سطرهای سند)
| ستون | نوع | توضیح |
|------|-----|-------|
| id | INTEGER | شناسه |
| journal_entry_id | INTEGER | شناسه سند |
| account_id | INTEGER | حساب |
| debit | REAL | بدهکار |
| credit | REAL | بستانکار |
| line_description | TEXT | شرح سطر |

## راهنمای نصب و اجرا

### مرحله ۱: نصب Python

1. به [python.org](https://www.python.org/downloads/) بروید
2. **Python 3.10 یا بالاتر** را دانلود و نصب کنید
3. هنگام نصب، گزینه **"Add Python to PATH"** را فعال کنید
4. نصب را با دستور زیر بررسی کنید:

```bash
python --version
```

### مرحله ۲: دانلود پروژه

پوشه `accounting_app` را در محل دلخواه کپی کنید، سپس در ترمinal (CMD یا PowerShell) وارد پوشه شوید:

```bash
cd accounting_app
```

### مرحله ۳: نصب کتابخانه‌ها

```bash
pip install -r requirements-desktop.txt
```

### مرحله ۴: اجرای برنامه دسکتاپ

```bash
python main.py
```

دیتابیس به‌صورت خودکار در مسیر زیر ساخته می‌شود:

```
C:\Users\<نام کاربر>\Documents\HesabdariApp\accounting.db
```

### اجرای نسخه وب React و Flask

رابط کاربری وب با **React، TypeScript و Tailwind CSS** ساخته شده و Flask API را فراهم می‌کند. در اجرای محلی، اگر `DATABASE_URL` تنظیم نشده باشد از SQLite محلی استفاده می‌شود؛ با تنظیم آن، برنامه به PostgreSQL (از جمله Neon) وصل می‌شود.

تمام مبالغ نسخه وب به **ریال** ذخیره، محاسبه و نمایش داده می‌شوند؛ قیمت هنگام ثبت کالا یا فاکتور را به ریال وارد کنید. در اولین اجرا پس از این تغییر، مبالغ قبلی فروشگاه که به تومان ذخیره شده بودند با مهاجرت خودکار و فقط یک‌بار در ۱۰ ضرب می‌شوند تا ارزش واقعی آن‌ها حفظ شود.

در صورت نیاز، فایل `.env.example` را به `.env` کپی کنید و تنظیمات ورود را عوض کنید. برای استفاده از Neon، مقدار `DATABASE_URL` را در `.env` بگذارید؛ از connection string دارای pooling در Neon استفاده کنید. بدون آن دیتابیس محلی SQLite استفاده می‌شود. هنگام اتصال به Neon، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را با همان حسابی تنظیم کنید که در آن دیتابیس ساخته شده است. فایل `.env` محرمانه است و در Git نادیده گرفته می‌شود.

ترمینال اول (سرور API):

```bash
python -m venv .venv
# Linux/macOS:
. .venv/bin/activate
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

در Windows PowerShell، به‌جای دو فرمان آخر از این‌ها استفاده کنید:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

ترمینال دوم (رابط React):

```bash
npm install
npm run dev
```

آدرس `http://localhost:5173` را باز کنید. ورود محلی آزمایشی: `admin / 123456`.

برای ساخت نسخه تولیدی React و اجرای یکپارچه از Flask:

```bash
npm run build
python app.py
```

سپس `http://127.0.0.1:5000` را باز کنید.

### استقرار نسخه وب روی Vercel

1. پروژه را به GitHub پوش کنید و در Vercel از **Add New → Project** مخزن را Import کنید. فایل `vercel.json` فرمان ساخت React را اجرا می‌کند و فایل‌های React را کنار Flask Function قرار می‌دهد.
2. در **Environment Variables** مقدار اتصال Neon را با نام `DATABASE_URL` اضافه کنید. از connection string وب‌سایت Neon استفاده کنید و رمز را فقط در تنظیمات Vercel وارد کنید؛ آن را داخل Git یا کد قرار ندهید.
3. متغیرهای ورود و `SECRET_KEY` را در Vercel تنظیم کنید. برای دیتابیس، URL مربوط به دیتابیس اصلی را فقط برای **Production** بگذارید؛ برای **Preview** یک branch جدا در Neon بسازید و URL همان branch را تنظیم کنید تا اطلاعات آزمایشی وارد دیتابیس اصلی نشود.

   - `DATABASE_URL`: رشته اتصال pooler مربوط به دیتابیس/branch همان محیط.
   - `SECRET_KEY`: یک مقدار تصادفی و محرمانه (مثلاً خروجی `python -c "import secrets; print(secrets.token_hex(32))"`).
   - `ADMIN_USERNAME`: نام کاربری مدیر.
   - `ADMIN_PASSWORD`: یک رمز عبور قوی و یکتا.

4. Deploy را بزنید؛ پس از اتمام، آدرس Vercel را باز کنید و با اطلاعاتی که برای `ADMIN_USERNAME` و `ADMIN_PASSWORD` تعیین کرده‌اید وارد شوید.

برای استقرار با CLI، پس از نصب و ورود به Vercel CLI، از ریشه پروژه دستور `vercel` را برای پیش‌نمایش و `vercel --prod` را برای انتشار نهایی اجرا کنید.

نسخه وب علاوه بر فروش و انبار، ثبت سند حسابداری دوطرفه، فهرست و جزئیات اسناد، دفتر کل، تراز آزمایشی و صورت سود و زیان را دارد. حساب‌های پیش‌فرض از کدینگ نسخه دسکتاپ می‌آیند؛ هر سند باید حداقل دو سطر و جمع بدهکار/بستانکار برابر داشته باشد.

**دیتابیس:** وقتی `DATABASE_URL` تنظیم شده باشد، هم اجرای محلی و هم Vercel از همان PostgreSQL نئون استفاده می‌کنند؛ در غیر این صورت اجرای محلی از `database/shop.db` استفاده می‌کند. دیتابیس محلی به Neon خودکار کپی نمی‌شود؛ پیش از استفاده از اطلاعات قبلی، باید آن‌ها جداگانه منتقل شوند. از connection string محیط Production در Preview استفاده نکن تا داده‌های آزمایشی به دیتابیس اصلی وارد نشوند؛ برای Preview یک دیتابیس/branch جدا بساز.

کالاهای نمونه دیگر به‌صورت خودکار هنگام شروع برنامه اضافه نمی‌شوند. این تغییر، کالاهای نمونه‌ای را که از قبل در فایل دیتابیس محلی یا Neon وجود دارند حذف نمی‌کند.

در نسخه وب، هشدار کمبود موجودی به‌صورت خودکار برای کالاهای با موجودی کمتر از ۵ نمایش داده می‌شود و با ثبت فاکتور، موجودی کالا به تعداد فروش‌رفته کاهش می‌یابد. فهرست‌های محصولات، مشتریان، انبار، فاکتورها و ردیف‌های فاکتور امکان جست‌وجو دارند.

در فرم فاکتور می‌توان مبلغ را بین چند روش پرداخت (نقدی، کارت‌خوان، واریز و چند چک) تقسیم کرد. برای هر چک شماره، بانک و تاریخ سررسید ثبت می‌شود و در فهرست و جزئیات فاکتور نمایش داده می‌شود. تا زمان پاس‌شدن، مبلغ چک جزو پرداخت‌شده حساب نمی‌شود؛ پس از تایید پاس‌شدن هر چک در جزئیات فاکتور، مبلغ آن به جمع پرداخت‌شده اضافه و تاریخ تایید ثبت می‌شود.

## راهنمای ساخت فایل EXE (PyInstaller)

برای اجرا روی ویندوز **بدون نصب Python**:

### پیش‌نیاز

```bash
pip install pyinstaller
```

### ساخت exe

در پوشه پروژه:

```bash
pyinstaller build.spec
```

یا بدون فایل spec:

```bash
pyinstaller --onefile --windowed --name Hesabdari main.py
```

فایل اجرایی در پوشه `dist/` ساخته می‌شود:

```
dist/Hesabdari.exe
```

### نکات PyInstaller

- فایل `Hesabdari.exe` را می‌توانید روی هر ویندوزی کپی و اجرا کنید
- اولین اجرا ممکن است چند ثانیه طول بکشد
- آنتی‌ویروس‌ها گاهی فایل‌های PyInstaller را هشدار می‌دهند — این طبیعی است
- برای ساخت نصب‌کننده (installer) می‌توانید از [Inno Setup](https://jrsoftware.org/isinfo.php) استفاده کنید

## راهنمای استفاده

### ۱. سرفصل حساب‌ها
- از تب «سرفصل حساب‌ها» حساب‌های جدید بسازید
- ساختار: گروه → کل → معین → تفصیلی
- حساب‌های پیش‌فرض هنگام اولین اجرا ایجاد می‌شوند

### ۲. ثبت سند
- تب «اسناد حسابداری» → «سند جدید»
- حداقل ۲ سطر با جمع بدهکار = بستانکار
- فیلد «سررسید» برای پیگیری اسناد اقساطی

### ۳. صندوق
- «ورود وجه» یا «خروج وجه» برای ثبت سریع
- موجودی لحظه‌ای در بالای صفحه نمایش داده می‌شود

### ۴. گزارش‌ها
- بازه تاریخی را انتخاب کنید → «نمایش گزارش»
- خروجی Excel یا PDF بگیرید

### ۵. پشتیبان‌گیری
- منوی «فایل» → «پشتیبان‌گیری»
- فایل `.db` را در جای امن نگه دارید
